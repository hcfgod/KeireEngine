Engine capabilities · 0.4.0 source candidate

One toolchain.
Clear boundaries.

Kéire brings project management, content authoring, runtime systems, and release engineering together without turning them into one opaque process. Source capabilities are distinct from the active 0.3.2 catalog artifacts.

01

Project Hub

Create, discover, and open projects; select installed editors; browse templates; manage package tasks; and receive signed editor updates independently from project content.

02

Scene authoring

Work across dockable Scene and Game views with hierarchy, Inspector, multi-scene Play Mode, prefab overrides, recoverable dirty state, undo transactions, and structured diagnostics.

03

Rendering

Use an SDL_GPU platform layer with DXIL, SPIR-V, and MSL shader targets, material graphs, lighting, cameras, shadowing, viewports, render inspection, and GPU-safe retirement.

04

Asset pipeline

Import through isolated workers, resolve typed handles and fallbacks, rebuild catalogs atomically, cook deterministic packs, and validate content before publication.

05

C# gameplay

Build with the Unity-shaped 0.4.0 object model, direct Entity, Component, Prefab, and asset references, managed-state v2, multi-scene queries, runtime UI, rendering, audio, animation, and navigation services.

06

Runtime foundations

Rely on explicit ownership, reference-safe objects, typed events, application-owned time, bounded queues, deterministic frame order, jobs, memory domains, and replay support.

07

Authoring systems

Create typed assets with shared Shader, Material, and VFX graph selection, comments, clipboard remap, layout commands, bookmarks, diagnostics, schema migration, and executable VFX subgraphs.

08

Player builds

Resolve Build Support, validate target compatibility, cook content, assemble platform players, and preserve exact manifests, checksums, source modules, and licenses.

09

Release discipline

Use native installers, signed distribution catalogs, immutable packages, sanitizers, smoke modes, deterministic archives, and cross-platform validation scripts.

Built for inspection

Power is useful when it stays understandable.

Public APIs remain backend-neutral while private platform, rendering, JSON, HTTP, and native ownership stay behind explicit boundaries.

Observable by design

Structured diagnostic IDs, editor architecture panels, task progress, performance gates, validation manifests, and explicit failure states make system behavior inspectable.

Cross-platform by evidence

Windows and Linux x86-64 are directly validated across native packaging, sanitizers, editor/Hub workflows, and D3D12 or Vulkan. macOS support remains maintained but is not yet a tested public-download target.
