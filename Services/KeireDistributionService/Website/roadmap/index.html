Pre-1.0 roadmap

Progress without
pretending.

Kéire already has a broad engine and editor foundation. It is still early-access software, and production readiness depends on evidence across every supported platform.

Read the evidence reviewFollow development

Current phase

Foundation built. Closure active.

This page describes direction, not a dated promise. Status changes only when implementation, tests, documentation, packaging impact, and target-platform evidence agree.

Established

Runtime and lifecycle foundations

Application ownership, layers, events, time, references, jobs, memory domains, diagnostics, replay, and deterministic lifecycle contracts are implemented and tested.

Established

Project-first editor and Hub

Project discovery, templates, editor selection, scene authoring, dockable workspaces, task orchestration, package trust, and independent editor installations form a coherent desktop workflow.

Established

Assets, scripting, and player pipeline

Typed catalogs, isolated import, cooking, managed gameplay, Build Support, player assembly, package manifests, native installers, and SDK consumers have defined production paths.

Active

Rendering and authoring closure

Continue validating complete production slices across rendering, materials, animation, audio, UI, navigation, physics, and content-team workflows instead of counting isolated features.

Active

VFX catalog parity

Close the frozen capability catalog one tested effect family at a time, keeping disabled rows honest until CPU, GPU, authoring, diagnostics, and production coverage agree.

Active

Cross-platform release evidence

Grow sustained Windows, Linux, and macOS evidence for graphics backends, installers, sanitizers, performance budgets, signing, notarization, and packaged consumer workflows.

Ahead

Production release

A 1.0 date is intentionally not announced. The release gate is repeatable evidence: no critical lifecycle gaps, validated platform packages, complete public claims, and proven content-team workflows.

Help move a real gate

Contribute where evidence is thin.

Platform validation, focused tests, reproducible defects, documentation corrections, and complete subsystem slices are more valuable than speculative feature lists.
